# 关键词 → 真实意图词典

JD 措辞是招聘方的行话，不是可判定的要求。同一个词在不同上下文里要求的深度完全不同。本词典把高频词映射到**可判定的意图**，阶段 1a 读它。

## 使用规则

1. 命中词典只说明"这里有一个要求"，**不说明候选人满足它**。候选人侧的证据只能来自 Candidate KB。
2. 一个词命中后必须落到具体的 `requirement` 条目，带逐字 `sourceQuote`。
3. 词典不覆盖时，按 JD 原句直译，不得自行发挥。

## 技术栈类

| 模式 | 意图 | 追问口径 |
|---|---|---|
| 熟悉 / 掌握 / 了解 | 日常使用，能独立完成任务 | 生产中用过多久，独立做过什么 |
| 精通 / 深入 / 资深 | 独立做过关键决策 | 哪个决策是你做的，替代方案是什么 |
| 有过 … 经验 | 至少接触过一次 | 是生产环境还是练习 |
| 加分项 / 优先 / preferred | 非硬性门槛 | 没有也能投 |

## 职责范围类

| 模式 | 意图 | 追问口径 |
|---|---|---|
| 负责 / 主导 / 牵头 | ownership 要求 | 是独立负责还是团队负责你其中一块 |
| 参与 / 协助 / 配合 | participation 要求 | 你的具体产出是什么 |
| 独立负责 | 强 ownership | 必须有明确证据，否则是 R1 越界 |
| 搭建 / 从 0 到 1 | 创建权 | 是从零建还是在既有上演进 |
| 优化 / 治理 / 重构 | 改进权 | 前后指标对比，手段是什么 |

## 规模类

| 模式 | 意图 | 追问口径 |
|---|---|---|
| 高并发 / 大流量 | 量级要求 | 具体 QPS / DAU / 数据量 |
| 大规模 / 海量 | 量级要求 | 同上，不给量级的"大规模"不可判定 |
| 高性能 / 低延迟 | 指标要求 | P99 还是 P50，目标值多少 |
| 高可用 | 可用性要求 | 几个 9，故障如何处理 |

## 架构类

| 模式 | 意图 | 追问口径 |
|---|---|---|
| 架构设计 / 系统设计 | 设计权 | 你设计的边界是什么，权衡是什么 |
| 微服务 / 分布式 | 拓扑要求 | 拆分动机，一致性问题怎么解 |
| 中台 / 平台化 | 复用要求 | 服务谁，接入方多少 |
| 组件化 / 工程化 | 工具链要求 | 做了什么工具，谁在用 |

## 软素质类

| 模式 | 意图 | 追问口径 |
|---|---|---|
| 沟通协作 / 跨团队 | 协作要求 | 和谁协作，推动过什么 |
| 主人翁 / ownership | 责任要求 | 哪件事体现 |
| 抗压 / 快节奏 | 环境描述，非能力要求 | 不构成判定项 |

## 反模式（出现即警觉）

| 模式 | 为什么危险 |
|---|---|
| 只在 JD 标题里出现 architect / 专家 | 标题是 shape，不是 evidence。T14 §3：frame 识别必须在逐条资格匹配之后做 |
| 一段话里堆 20 个技术名词 | 关键词堆砌，无法区分必须与加分。逐句拆开再判定 |
| "有相关经验者优先"紧跟 20 项技术 | 把加分项写成门槛。标 `required: false` |
| 时代性描述（"紧跟前沿"/"当前热门"） | 无来源的时代判断。T6 Q8：只允许有来源的时代事实 |
