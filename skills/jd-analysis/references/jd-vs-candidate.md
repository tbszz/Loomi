# JD 与 Candidate 的边界

这两个集合必须分开。混在一起就会把"岗位要什么"变成" Candidate 会什么"。

## 两个不同的来源

| | JD 要求 | Candidate 能力 |
| --- | --- | --- |
| 来自 | 岗位文本、聚合记录 | `search_candidate_knowledge` 返回的事实与原文 |
| 身份 | 外部条件 | 已验证 / 用户陈述的证据 |
| 可信度 | 可能是 unverified | 必须能给出 `fact_id` 或引用 |
| 变化原因 | 岗位方更新 | Candidate 上传新材料 |

## 对照时的三条规则

1. **先写 JD 要求，再单独检索证据。** 不要在读到 JD 的瞬间就假定 Candidate 具备。
2. **无证据 = 无证据。** 检索不到就写"无证据/待核实"，不要写成"应该会"或"可能没有"。
3. **不补证据。** 对照表出现空缺时，正确输出是提示用户补充材料，而不是自己填一句。

## 禁止的说法

- "你符合这个岗位的要求"（只能说：以下 N 项有证据，M 项无证据）
- "你的匹配度是 82%" / "录取概率较高" / "竞争力排名前 20%"
- "建议你在简历里写上 xx 经验"（除非 `resume-tailoring` 且该经验确有其证据）

## 允许的说法

- "JD 要求 3 年经验；材料里能确认的是 1 段 8 个月实习，年限无证据。"
- "这项为 unverified：来源未给出学历要求。"
- "对照结果：5 项有证据、2 项部分满足、3 项无证据。"
