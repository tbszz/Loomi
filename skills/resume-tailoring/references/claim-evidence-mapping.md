# Claim → Evidence 映射

## 规则

写进简历正文的每一条事实性内容，必须能落到下面两者之一：

1. `fact_id` —— 来自 `search_candidate_knowledge` 返回的结构化事实；
2. 原文引用 + 位置 —— 来自 Candidate 文档的逐字片段。

**两者都没有 → 只能进 gaps。**

## 建立方式

```text
Claim：独立完成订单模块的接口设计与联调
依据：fact_id = f_0123（type=project）
原文：「负责订单模块接口设计与联调」
判定：可写

Claim：将接口响应时间优化 40%
依据：无（材料中未出现该数字）
判定：进 gaps，需用户提供来源或删除
```

## 允许与不允许的改写

| 原文 | 允许 | 不允许 |
| --- | --- | --- |
| 参与了 XX 项目 | 参与 XX 项目，负责其中 YY 部分 | 独立负责 XX 项目 |
| 使用过 React | 使用 React 完成…… | 精通 React |
| 协助完成测试 | 配合完成测试工作 | 主导测试体系建设 |
| 团队获得 X 奖 | 所在团队获得 X 奖（本人负责……） | 获得 X 奖 |
| 用户量约 1 万 | 用户量约 1 万（如有来源） | 用户量超 10 万 |

## JD 关键词的处理

JD 提到但 Candidate 无证据的技能：**不能写进简历**。

正确做法：

- 当作 gaps 提示用户："岗位要求 A，目前材料里没有 A 的证据，是否确实使用过？"
- 若用户确认并补充材料，走正常事实入库流程后再使用。

## gaps 的输出格式

```text
未写入正文（缺证据）：
- 想写：……
- 原因：材料中未找到依据
- 需要确认：……
```
