# 岗位检索与匹配验收

2026-10-27，本轮在已接入的统一岗位缓存上核验检索、分页和资格规则。三个合成候选人场景用于复现边界问题，另使用一位已有绑定候选人的有效背景事实进行匿名验收。它们不是整体用户匹配率统计，也不代表所有自然语言门槛都已被自动识别。

| 场景 | 调整前首屏 | 调整后首屏 |
| --- | --- | --- |
| 2027届本科技术岗 | 20条均为聚合摘要 | 20条均有完整正文；1条检查通过，19条待核实 |
| 市场运营转后端 | 12条已判定硬条件冲突 | 20条均有完整正文；20条待核实 |
| 五年Java后端 | 1条已判定硬条件冲突 | 20条均有完整正文；6条检查通过，14条待核实 |
| 已有绑定候选人 | 本轮首次测量 | 20条均有完整正文；20条待核实 |

四组首屏均未出现已判定硬条件冲突的岗位，前后两页无重复。候选人样本通过现有数据库服务的所有权和来源验证读取，报告只记录匿名引用及事实数量，不导出候选人原文。多条教育记录、缺少相关领域年限或技能证据等情况继续保留待核实。

最终代码通过新增检索验收、既有资格检查、完整 `npm test` 和 `npm run build`；最终测试期间的源码指纹已记录在本地报告中。独立审查报告的问题修复后均通过复核。

本轮修复分页后才判断资格、官网泛社招入口覆盖明确校招标题、重复届别误报、中文学历漏判、优先项变硬要求、项目/无关行业年限误用、技能任选范围吞掉独立要求等问题。三项独立代码审查问题及追加边界复现已修复，并通过复核。702条源记录的招聘类型得到修正，保留原类型和完整SQLite备份；43,541条源记录身份全部保留，19张非岗位表与备份完全一致，重复清理为零变更。

从抽样结果中选择6个岗位，通过滴滴、东方财富、迅雷、VAST、MiniMax共5个已安装官方适配器读取公开列表；6条均仍能找到，缓存要求文本与官网列表正文一致。这只是6条岗位在抽样时的官方列表观察，不能保证全库持续开放，也没有执行任何投递操作。各条URL、要求片段、观察时间及测试结果保存在本地 `data/job-audits/job-search-acceptance.json`。

可重复运行：

```powershell
npm run jobs:check-search
# 可选：使用指定已有对话绑定的候选人；只在临时数据库副本上读取。
npm run jobs:check-search -- --conversation-id=实际对话ID
node --test server/jobSearchAcceptance.test.js
```

命令默认仅使用缓存，不调用模型，也不刷新官网。实时抽查证据与验收时点绑定；重新运行缓存验收不会声称已经完成新的实时抽查。
